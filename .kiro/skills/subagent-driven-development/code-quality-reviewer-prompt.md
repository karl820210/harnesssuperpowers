# 程式碼品質 Reviewer Sub-agent Prompt 模板

派遣 code quality reviewer sub-agent 時使用此模板。

**目的**：驗證實作是否建構良好（乾淨、有測試、可維護）。

**只在 SDD 合規 review 通過後才派遣。**

```
invokeSubAgent:
  name: general-task-execution
  prompt: |
    你正在審查程式碼品質。SDD 合規已通過（功能正確），現在檢查實作品質。

    ## 實作內容

    {從 implementer 回報中貼過來}

    ## 變更的檔案

    {列出變更的檔案，或提供 git diff 範圍}

    ## 檢查項目

    ### 程式碼品質
    - 關注點分離是否清晰？
    - 錯誤處理是否適當？
    - 型別安全（若適用）？
    - DRY 原則是否遵循？
    - 邊界條件是否處理？

    ### 架構
    - 設計決策是否合理？
    - 效能考量？
    - 安全考量？

    ### 測試
    - 測試是否真的測試邏輯（不只是 mock 行為）？
    - 邊界條件是否有測試覆蓋？
    - 測試是否清晰可維護？
    - 所有測試是否通過？

    ### 檔案組織
    - 每個檔案是否有單一明確職責？
    - 單元是否可獨立理解和測試？
    - 是否遵循 plan 定義的檔案結構？
    - 這次變更是否讓檔案變得過大？

    ## 嚴重度分級

    **Critical（必須修）**：bug、安全漏洞、資料損壞風險、功能壞掉
    **Important（應該修）**：架構問題、可維護性問題、測試覆蓋缺口
    **Minor（可以修）**：命名改善、註解補充、小重構機會

    ## 回報格式

    ### 優點
    [具體列出做得好的地方]

    ### 問題

    #### Critical
    [file:line — 問題 — 為什麼重要 — 如何修]

    #### Important
    [file:line — 問題 — 為什麼重要 — 如何修]

    #### Minor
    [file:line — 問題 — 建議]

    ### 評估
    **可以合併嗎？** Yes / No / 修完後可以
```
